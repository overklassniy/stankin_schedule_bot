# Политика безопасности

## Поддерживаемые версии

Проект находится в активной разработке, безопасность гарантируется только
для последнего релиза на ветке `master`.

| Версия | Поддержка         |
| ------ | ----------------- |
| master | Да                |
| прочие | Нет               |

## Сообщение об уязвимости

Если вы обнаружили уязвимость в безопасности проекта, **не создавайте
публичный issue**.

Сообщите о ней приватно одним из способов:

* Электронная почта: `overklassniy@users.noreply.github.com`
* Приватное сообщение через GitHub: упомяните `@overklassniy` в приватном
  обсуждении Security Advisory.

В сообщении укажите:

* Описание уязвимости и её последствия.
* Шаги для воспроизведения или proof-of-concept.
* Затронутые версии и компоненты.
* Возможные способы устранения (если известны).

## Сроки реагирования

* Подтверждение получения сообщения — в течение 72 часов.
* Оценка критичности и план устранения — в течение 7 дней.
* Выпуск исправления — в зависимости от критичности, как правило в течение
  30 дней. Для критических уязвимостей — быстрее.

## Правила ответственного раскрытия

Просим не публиковать информацию об уязвимости до выпуска исправления.
Мы готовы указать вас в списке благодарностей по согласованию.

## Что не считается уязвимостью

* Проблемы, требующие физического доступа к серверу или учётным данным.
* Самостоятельные атаки на инфраструктуру Telegram или Moodle.
* Содержание расписания или ошибки парсинга, не влияющие на безопасность.
* Проблемы сторонних зависимостей без подтверждённого вектора атаки в
  рамках проекта — сообщайте их напрямую в репозитории соответствующих
  библиотек.
