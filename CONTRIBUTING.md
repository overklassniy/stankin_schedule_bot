# Участие в проекте «СТАНКИН Расписание»

Спасибо за интерес к проекту! Любой вклад приветствуется: сообщения об
ошибках, идеи улучшений, документация, переводы, исправления кода.

## С чего начать

1. Прочитайте [README](README.md) и раздел [Архитектура](docs/architecture.md),
   чтобы понять устройство бота.
2. Перед началом работы создайте issue с описанием задачи и дождитесь
   ответа мейнтейнера, чтобы не дублировать чужую работу.

## Сообщение об ошибке

Используйте шаблон `Bug report` на странице
[New issue](https://github.com/overklassniy/stankin_schedule_bot/issues/new/choose).
Опишите шаги воспроизведения, ожидаемое и фактическое поведение, приложите
логи и параметры окружения.

## Предложение улучшения

Используйте шаблон `Feature request`. Опишите сценарий использования и
какую проблему решает предложение.

## Настройка окружения

Подробная инструкция — в [Установке](docs/installation.md). Кратко:

```bash
git clone https://github.com/overklassniy/stankin_schedule_bot.git
cd stankin_schedule_bot
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux/macOS
pip install -r requirements.txt
cp .env.example .env
# укажите BOT_TOKEN в .env
python bot.py
```

Для парсинга PDF требуется установленный Ghostscript.

## Стиль кода

* Python 3.13, асинхронный стиль aiogram 3.
* Все комментарии и docstring — только на русском языке в стиле Google.
* Запрещены эмодзи и декоративные символы Unicode в комментариях и
  документации (см. [Правила документирования](.devin/rules/documentation.md)).
* Имена коммитов — на русском языке, в стиле журнала изменений
  (см. [Правила коммитов](.devin/rules/commits.md)).
* Не добавляйте новые зависимости без необходимости. При добавлении
  проверяйте актуальную стабильную версию и фиксируйте её в
  `requirements.txt` с верхней границей (например, `aiogram>=3.31,<4`).

## Структура проекта

```
bot.py            Точка входа

docs/             Документация
```

Подробно — в [Архитектуре](docs/architecture.md).

## Процесс отправки изменений

1. Сделайте fork репозитория и создайте ветку от `master`:
   ```bash
   git checkout -b feature/короткое-описание
   ```
2. Внесите изменения. Один pull request — одна логическая задача.
3. Убедитесь, что бот запускается и ваши изменения работают локально.
4. Заполните шаблон описания pull request.
5. Откройте pull request в репозиторий `overklassniy/stankin_schedule_bot`,
   базовая ветка — `master`.

## Проверка перед отправкой

* Бот запускается без ошибок: `python bot.py`.
* Новые команды и обработчики покрыты ручной проверкой в тестовой группе.
* Не закоммичены секреты, `.env`, файлы БД и кэш PDF (см. `.gitignore`).
* Комментарии и docstring — на русском языке.

## Коммиты

Сообщения коммитов оформляются на русском языке в стиле журнала изменений:

```text
Добавлена отправка расписания на неделю

- Добавлена команда /week
- Обновлён планировщик
- Исправлена обработка пустого расписания
```

Подробнее — в [Правилах коммитов](.devin/rules/commits.md).
